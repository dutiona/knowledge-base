## Decisions

None is BLOCKING: each has a safe, reversible default Michaël may override at approval.

- **D1 (#638) The cuts come from the provider that embeds the vector.** A new
  `embed_swap.space_embedder(conn, space) -> Callable[[list[str]], tuple[list[list[float] | None], Cuts]]` resolves the
  space's provider once (`get_provider(cfg=declared_provider_config(conn, dict(space)))`, so the ADR-0015 §3 identity
  check still runs before the first request), and each call runs `embed_with_cuts` at `matryoshka_base_dim or dim`,
  then truncates to `dim` for a Matryoshka space. `backfill_space` and `redact_store.rewrite` both use it, so the
  rewrite's Matryoshka branch is the one the backfill tests already run, and the rewrite's provider lookup goes through
  `embed_swap.get_provider`, which `tests/test_redact_store.py`'s `vectors` fixture already patches.
  - Rejected: `ingest._embed_with_config` returning cuts (its five callers change shape, and the tests patching
    `knowledge_base.ingest.embed` stop intercepting); a rewrite-local provider lookup (a second Matryoshka copy, and
    the fixture's `embed_swap.get_provider` patch would miss it); counting tokens before embedding (a second copy of
    the provider's cut rule).
- **D2 (#638) What `truncated_chunks` reports.** `rewrite()`'s result gains `truncated_chunks`: every chunk of the
  active space stored cut, read from the table after the run through a new `embed_swap.truncated_chunks(conn,
  space_name) -> list[dict]`, which is `backfill_space`'s closing query moved unchanged (same keys, chunk-id order;
  `[]` when there is no active space). A rerun that finishes an interrupted rewrite still lists what the interrupted
  run stored, which is #620's property. The read-only `redact` report and the exit code are unchanged.
  - Rejected: only this run's cuts (the finishing rerun re-embeds nothing and would list none); listing them in the
    read-only report too (it describes what a rewrite would change).
- **D3 (#638) Where and when the record is written.** Inside `_apply`'s single transaction, right after the chunk's
  `UPDATE chunks` (the v4 trigger `chunks_au_truncations` deletes a chunk's records when its content changes, so a
  record written before the `UPDATE` would be erased) and only beside a stored vector. The cut is keyed by chunk id,
  never by batch position. The statement stays inline, as in `backfill_space`.
  - Rejected: writing it after `_apply` commits (a crash between the two leaves a cut vector with no record); a
    one-statement `record_truncation` helper (two callers of one `INSERT`).
- **D4 (#643) What "none of them" covers.** The rows a failed job leaves uncommitted, which the defect names: "rows
  the failing job wrote before it raised are committed along with the failure status". Both failure branches of
  `_JobWorker._tick` start with `conn.rollback()`. A unit a dispatcher commits itself stays: extraction's and the
  figure writers' stores are each one transaction that commits or rolls back whole, and `auto_relate` commits each
  `similar` edge through `add_relationship`. Those edges are independent, idempotent derived data that a rerun
  recomputes, so a failed scan keeping the edges it finished is correct, not a leak. A completed job's leftover writes
  still commit with `completed`, because `auto_relate`'s trailing below-threshold `DELETE`s have no other commit; this
  differs on purpose from #642's MCP call boundary, which rolls back a forgotten commit on return. Item 5 tests this
  boundary explicitly (a committed unit stays, the uncommitted rest goes).
  - Rejected: whole-job atomicity, either by a savepoint around `_dispatch` or by making `auto_relate` compute every
    edge first and write them in one transaction at its end. It would discard a long scan's finished edges on a late
    failure, and the savepoint form would hold SQLite's one write lock for the whole scan, so concurrent ingests would
    fail on `busy_timeout`. Michaël may still choose the compute-then-write form; it changes `auto_relate`, not the
    worker.
  - Rejected: merging the two failure branches (the `ExtractionError` one keeps its structured result).
- **D5 (#643) Progress never commits a job's writes.** `on_progress` notes `opened = not conn.in_transaction` before
  its `UPDATE jobs SET progress`, and commits only when `opened`. Inside a job's open transaction the progress row
  rides with it: it lands with the job's own commit or goes with its rollback. As read, no dispatcher reports progress
  with writes open today (extraction and figures report before their store's transaction, `auto_relate` after
  `add_relationship` commits), so no visible progress changes; the rule makes the acceptance hold for any job.
  - Rejected: a second connection for progress (SQLite's one writer: it waits out `busy_timeout` and fails the job);
    skipping progress while a transaction is open (drops messages for nothing); leaving the commit (a job that writes,
    reports progress, then raises keeps its rows).
- **D6 (#643) The reproduction.** The failing test is the reproduction, through the real `_JobWorker._tick`, with the
  dispatcher seam the neighbouring tests use (`knowledge_base.extraction.extract_structure` patched). The commit body
  cites `auto_relate`'s uncommitted stale-edge `DELETE` (src/knowledge_base/auto_relate.py, the below-threshold branch)
  as the instance reachable today. Calling `_tick` once on the test's connection is deterministic, with no thread.
  - Rejected: a committed real-`auto_relate` failure (its one in-code raise needs a float32 cosine above 1.0, listed
    under Surfaced as accepted).
- **D7 (#639) The test.** A new `tests/test_agent_instructions.py`. A section is the match of
  `^## Verify\n.*?(?=^## |\Z)` (MULTILINE, DOTALL) on the file's UTF-8 text; each of the three files must hold one
  whose body (the match after its heading line) is not blank, so three missing or emptied sections cannot compare
  equal; `CLAUDE.md`'s and `GEMINI.md`'s must equal `AGENTS.md`'s
  byte for byte (`AGENTS.md` is the reference: the release checklist runs that one). The message says to edit the
  three together.
  - Rejected: `tests/test_lean_surface.py` (its subject is the HTTP surface); generating two copies from one (a build
    step to replace one test); a fence-aware parser (no `## ` line sits inside the fence).
- **D8 (#640) All three defaults go, with no new test.** `OllamaProvider.embed`, `OpenAICompatProvider.embed` and
  `ONNXProvider.embed` take `model: str`. Every caller passes `model=`; basedpyright, in the Verify list, reports any
  caller that relied on a removed default as a missing argument. The Protocol already has none. The test fakes'
  own `model="x"` defaults (tests/test_embed_spaces.py, tests/test_db.py) are not provider classes and stay.
  - Rejected: a signature-introspection test (it checks shape, not behaviour).
- **D9 (#644) The rewritten test.** It asserts, on `_extract_pdf_markdown(pdf, image_dir=image_dir)`: `page_map` is
  non-empty (the markdown path ran, not the flat fallback); at least one `knowledge_base.chunking.IMAGE_REF_RE` match

  - Rejected: `"![" in text` (passes on a stray bracket); an exact count (tests pymupdf4llm's detection, not the
    contract).
- **D10 (#644) The tesseract `skipif` goes.** Measured 2026-11-22 on 1.27.2.1 with tesseract hidden from `PATH`

  - Rejected: keeping it (an unneeded skip is the hole #465 hid in).
