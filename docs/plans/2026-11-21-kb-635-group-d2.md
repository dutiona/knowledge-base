# #635 — follow-up group D2: docs build, release gate, dead embed path, image verify, re-embed truncation report

## Outcome

The Sphinx build emits no warning, and the `## Verify` list fails on any new one (`-W`, every page reread), with branch
plans excluded. When a branch changes an image input, the Verify list builds `HEAD`'s `git archive` into an image,
bounded to 16 CPUs and 32 GiB, smoke-imports the server offline and removes the image, whether the smoke passed or not.
The release checklist's quality gate is that list plus the slow tests, with no copy of the list. `embeddings.py`
builds providers only from a `ProviderConfig`. `backfill_space`, the backfill MCP tool and
`knowledge-base-ingest re-embed` list each stored chunk of the space that was cut to fit `max_input_tokens`, by chunk
id, `source_uri` and token counts, never its text, at no extra `/tokenize` request. The list survives an interrupted
and resumed backfill, because each cut is recorded with its vector (schema v4). One PR, six commits (five members and
one boy-scout fix), closes #576, #586, #605, #617, #620 and #635.

## Decisions (defaulted: safe and reversible; Michaël overrides at approval)

1. **#620, mechanism.** Bounding stays in `OpenAICompatProvider`, the one place it happens, and that is also where
   each cut is already counted before and after (for its INFO line). The cuts are per-call data, so they travel in a
   return value, never on the cached provider shared by FastMCP's threads.
   - `_bounded` returns `(texts, cuts)`, `cuts` mapping position to (tokens counted, tokens kept).
   - A module function `embed_with_cuts` returns them for an `OpenAICompatProvider` and `{}` for any other.
   - The `EmbeddingProvider` Protocol and its roughly 20 test fakes stay as they are.
   - Rejected:
     - Counting again in `backfill_space` doubles the `/tokenize` requests per chunk and copies `_fit`.
     - An `embed` keyword or a new return type changes every provider and fake for one consumer.
     - A `ContextVar` hides the data flow.
   - This is the same "only a counting provider carries a limit" assumption `split_inputs` makes.
2. **#620, a durable record (recommended; Michaël decides at approval).** A backfill is resumable: it commits each
   batch, and a rerun after a failure skips the chunks already stored. So a report built only from one run's memory
   misses the cuts an interrupted run stored, and the acceptance asks for "each truncated chunk". The record is
   therefore kept with the vector, as `embed_refusals` (#579) keeps a refusal.
   - **Schema v4**, a new table, in the same shape as `embed_refusals`:
     `embed_truncations(chunk_id INTEGER NOT NULL REFERENCES chunks(id) ON DELETE CASCADE, space_name TEXT NOT NULL
     REFERENCES embed_spaces(name) ON DELETE CASCADE, tokens_before INTEGER NOT NULL, tokens_after INTEGER NOT NULL,
     PRIMARY KEY (chunk_id, space_name))`.
   - **A trigger**, `chunks_au_truncations AFTER UPDATE OF content ON chunks WHEN old.content IS NOT new.content`,
     deletes a chunk's rows when its text really changes: a rewrite drops the chunk's vectors, and the cut no longer
     describes its text. The `WHEN` matters because `redact --rewrite` sets `content = coalesce(?, content)` for a
     metadata-only or URI-only change and keeps the vector, and `UPDATE OF content` fires on any `SET` of the column.
   - **Writing:** `backfill_space` inserts a row in the same transaction as the cut vector.
   - **Reporting:** `truncated_chunks` is read from the table: every chunk of the space stored cut, by
     `{"chunk_id", "source_uri", "tokens_before", "tokens_after"}` in chunk-id order, `[]` when none. A resumed
     backfill therefore still lists the cuts its interrupted run stored.
   - **Lifecycle:** `cleanup_space` and a failed `re-embed` (which deletes its space) remove the rows by cascade.
   - **Consequence:** the next deployment runs `knowledge-base-ingest migrate` with the unit stopped, as v3 did. The
     release checklist's Step 4 already migrates. A space backfilled between #604 and v4 has its earlier cuts
     unrecorded; a `re-embed` lists them.
   - **The name:** not `chunks_*`, because those keys are counts. `re_embed` carries the list. The CLI prints that
     dict, and the MCP tool returns `backfill_space`'s.
   - **No log line is added:** the provider's INFO line keeps the counts, and the result names the chunk.
   - **Out of scope:** folder summaries and queries. #604 truncates them by design, and no reingest restores them.
   - **Alternative, if Michaël declines a schema bump:** no table. The result lists only this run's stored cuts,
     collected in the write loop. Each cut also gets a WARNING line, `chunk %d: stored cut from %d to %d tokens to fit
     %s=%d; reingest its document for full coverage` (chunk id and counts, no text, no source), so an interrupted
     run's cuts stay in the server log. That drops the `migrate.py`, `db.py` and schema-docs edits and the
     migration test, and replaces the resume test with a `caplog` assertion.
3. **#576.**
   - Non-ADR pages get explicit toctree entries, so a new page fails `-W` until someone places it. ADRs get a `:glob:`
     toctree on `design/adr/*`, in number order.
   - Both broken links become GitHub links on `master`, because neither target is part of the build. `insights/`
     stays excluded (#122).
   - `-W` enters the gate as a docs-build line in the Verify list. `-E` makes it reread every page, so a stale
     `docs/_build` cannot hide a warning in an unchanged page.
   - `conf.py` excludes `plans` (memory-engine's rule): without that, `-W` fails on every planned branch, this one
     included.
4. **#617.**
   - **Trigger paths:** the issue's four, plus `.python-version`. The image's `uv sync` reads `.python-version`
     against the base image's Python (`UV_PYTHON_DOWNLOADS=never`), which no other step does.
   - **Paths left out:**
     - `src/`: the test suite covers it, and watching it would make the heavy step run on nearly every PR.
     - The licences: `pyproject.toml` names them in `license-files`, so `uv sync` already reads them.
     - `.archive-commit` and `.gitattributes`: `tests/test_container_build.py` covers them.
   - **Guard:** an executable `git diff --quiet origin/master...HEAD -- <paths>`, not prose, so nobody skips it by
     judgment. A missing `origin/master` exits 128 and a stale one widens the diff: both lead to a build.
   - **Cleanup:** a subshell keeps the smoke's status and removes the image. It exits with the smoke's status when
     the removal succeeds, and with the removal's failure otherwise, so a left-behind image never passes. A failed
     build tags nothing, so the build's own failure exits before the `rmi`. The variable is `rc`, because `status`
     is read-only in zsh.

   `tests/test_redact_store.py`'s `lambda **_kw` fake call it; `embed(texts, model: str, expected_dim=None, *,
   _provider_cfg: ProviderConfig)`; and `OllamaProvider(base_url: str)`. `_get_ollama_url` stays: `llm.py` and

   amendment says "The bare-name `OpenAIProvider` keeps its literal endpoint". Its body is not rewritten.
